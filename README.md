# cartovox.org

The public site for [CartoVox](https://cartovox.org): simulate a planet, draw its
illustrated atlas, and write beside the same world in a desktop studio.
A static site: a landing page, guide, release archive and legal pages, no build step, no framework,
with self-hosted assets and a live Discord widget. A Cloudflare Worker with static assets serves it straight from this repository,
together with the Delta service CartoVox's Delta builds talk to (`worker/`).

## Positioning and onboarding

Lead with one living world used every way: simulate it, map it, build on
it, write in it, play in it. The home page stays short (about a minute to
read): one sentence per idea, detail on `/features/`, how-to in `/guide/`.
“How it compares” names kinds of tools (a map painter, a worldbuilding wiki,
a writing app, a virtual tabletop, a city generator), never products or
trademarks. Every product image is a real screen from a sandboxed build of
the app; do not substitute mock-ups. The 1.1 screenshots were captured from
the app's main branch (1.0.2 in development, released as 1.1) at 1600 × 1000,
2×, from worlds built in one click from Discover (Uzbadnyxil, a ringed
world; The Gilded Rim, a disc world); see `tools/studio-shots/README.md`.

## Design language

The site wears the app's Survey Sheet (`<app>/web/survey-sheet.css`): a
sheet on a cartographer's desk, not a product template. Keep to it:

- **The desk.** Dark ink with faint registration crosses every 160 px; on
  a wide window both margins carry a printed map's degree border.
- **Plates.** Each home section is a numbered plate (`.plate-no`: Plate I…VI,
  in DM Mono), the Features areas are numbered in the jump bar. `.sheet`
  draws crop marks at a block's corners; `.shot` frames a screenshot on a
  ruled mat with an inner neatline.
- **Four faces, one job each.** Newsreader for headlines and prose, Archivo
  for the interface and the condensed margin capitals (`.eyebrow`), DM Mono
  for figures, folios, captions and field notes, Cinzel only for map
  lettering (plate titles, the legend's cartouche).
- **Colour.** Brass for action and the current place, one red (`--stamp`)
  only for marginalia (the Notice slip, the “Simulated, not painted”
  stamp), parchment (`.paper-sheet`, the ledger's CartoVox column) for an
  inset printed on paper. Square corners (2 px at most); no pills.
- **Furniture is the app's.** The compass roses are drawn by the app's
  Compass designer and the globe is the app's example world; rebuild them
  with `tools/build-furniture.py <app>` and `tools/build-globe.py
  <app>/web/title/starter-world.webp`. Annotation pins on Plate I point at
  real things in that screenshot; move them (`.pin-1`…`.pin-5`) if the
  screenshot changes.

## Shared header and footer

Every page uses one pattern, in this order: the skip link, the
`<p class="soon-banner">` release note (marked `RELEASE-1.1`), `<header
class="nav">` with the brand and `<nav class="nav-links" id="nav-links"
aria-label="Main">` (Features, Discover, Guide, Releases, then a gold
Download button that is repeated as `.nav-cta-mobile` inside the menu), the
`#nav-toggle` menu button, and a `<noscript>` copy of the links. Mark the
current page with `aria-current="page"`. The footer has the lockup, three
link columns (CartoVox, Learn, Legal, each headed by `<p class="footer-h">`)
and one fine-print line. `features/index.html` holds the canonical copy;
`tools/site_chrome.py` copies it into the guide and release pages, and
`tools/build-legal.py` carries it for the EULA and notices. Below 860 px
the links fold into the menu. `js/site.js` handles the toggle, Escape and
focus.

### What to flip when CartoVox 1.1 ships

The site may go live before 1.1 does, so until then it must stay true today:
downloads are 1.0.1, and 1.1 additions are tagged.

1. Delete every `<p class="soon-banner">` and its `RELEASE-1.1` comment
   (`grep -rl RELEASE-1.1 --include=*.html .`), or hide them all at once by
   setting `.soon-banner { display: none; }` in `css/site.css`.
2. In `index.html` `#download`, replace the `download-soon` note, the
   “Current release” heading, the release-notes link, the four file links,
   sizes and SHA-256s with 1.1's (also marked `RELEASE-1.1`).
3. Remove the “New in 1.1” tags (`new-tag`) and the sentence about them in
   `features/` and `discover/` page heads, and the FAQ entry “When is
   CartoVox 1.1 out”; then `python3 tools/build-faq-schema.py`.
4. Set `RELEASED_11 = True` for the guide and rebuild it, run
   `build-releases.py`, then `subset-fonts.py` and `stamp-assets.py`.

`/guide/` is the newcomer route: install, the six workspaces, then seven
first-hour tasks with app paths and visible results, linking to one
reference page per workspace. Edit `tools/guide-src/<page>.html` and run
`python3 tools/build-guide.py`; never edit the generated `guide/*/index.html`.
Use the app's own labels, checked in the app. Until 1.1 ships, anything new
in 1.1 carries the `{new}` tag ("New in 1.1 · coming soon") and the 1.0.1
way stays described; at the release set `RELEASED_11 = True` and rebuild.
The guide and the release pages take the shared header and footer from
`features/index.html` (or `index.html`) through `tools/site_chrome.py`, so
rebuild both after a nav change:

```bash
python3 tools/build-guide.py
python3 tools/build-releases.py <app>/.github/release-notes --through <latest released version>
python3 tools/stamp-assets.py
```

Bound the promises: continuity checks flag supported scene and link issues;
they do not guarantee all prose agrees with the world. Rebuilds can change
geography, and author work follows surviving places. Reproducibility describes
the physical simulation with the same seed, saved settings and simulation
version; cross-environment pixel identity is not promised. CartoVox 1.0 is
free for everyone, with no invite or access code.

## Downloads

From 1.0 the installers are published on GitHub Releases
(`harsit14/cartovox-releases`). Every download button on the site uses a stable
per-file link, `https://github.com/harsit14/cartovox-releases/releases/latest/download/<file>`,
so the file names in `index.html` must match the release's assets exactly;
`/download` and `/beta` redirect to the latest release page. GitHub appears
only in download links and in the privacy page's account of the update check;
keep it out of other copy. Discord stays the community and support door.
Sizes on the homepage are decimal MB from the release's byte counts, and the
SHA-256s are copied from its `SHA256SUMS.txt`.

Keep homepage copy brief: direct section labels, one outcome per feature, and
one or two sentences per introduction. Put reference detail in the guide.
Every homepage section has an anchor and an accessible heading. The longer
creator comments use native “Read feedback” disclosures; preserve the full
quotes, credits, source links and artwork when editing the surrounding copy.

## Deploying on Cloudflare

The site is the `cartovox` Worker (Workers & Pages → cartovox), connected to this
repository with Workers Builds: production branch `main`, no build command, deploy
command `npx wrangler deploy`, which reads `wrangler.jsonc`. The Worker serves the
repository's files as static assets (minus `.assetsignore`), honours `_headers` and
`_redirects`, and answers 404s with `404.html`. `cartovox.org` is its custom domain.

Every push to `main` redeploys; other branches get preview versions.

## The Delta service

Delta builds of CartoVox register each computer under an access code and send a
usage report to `https://cartovox.org/v1/…`. The code is written and tested in
the app repository (`services/delta-service/`); copy it here with

```bash
python3 tools/sync-delta-service.py <app>
```

and push. The D1 database (`cartovox-delta`) is bound in `wrangler.jsonc`; the one
thing set by hand is the Worker's encrypted **`ADMIN_TOKEN`** secret (Workers & Pages →
cartovox → Settings → Variables and Secrets), the password for `/admin`. The service creates its
tables and loads the issued access codes itself on first use. The report is at
`https://cartovox.org/admin`; revoking a code and reading raw data are described in
the app repository's `services/delta-service/README.md`.

In the `cartovox.org` Cloudflare zone, **Always Use HTTPS** is enabled and HSTS
is set to 12 months. Cloudflare serves HSTS for the whole domain, including
Worker responses. Subdomains and preload are off because they have not been
audited. Keep HTTPS available before changing these settings; HSTS stays in
visitors' browsers for its max age.

## Regenerating images

The current logo sources are the supplied VectorCraft **Atlas Compass v3**
exports in `brand/v3/`, with their original usage notes. The older v2 masters
remain in `brand/` for reference. World plates live in a local CartoVox library,
and studio screenshots come from a sandboxed run of the app.

```bash
python3 tools/build-images.py --brand brand/v3 --worlds <library>/worlds --shots <shots-dir>
python3 tools/build-legal.py <app>/EULA.md <app>/THIRD-PARTY-NOTICES.md
python3 tools/build-releases.py <released-notes-dir> --through 1.0.1
python3 tools/build-discover.py <app>      # Discover gallery pictures and cards from the app's catalogue
python3 tools/build-faq-schema.py          # FAQPage JSON-LD, derived from the FAQ on /features/
python3 tools/subset-fonts.py              # Rebuild self-hosted fonts after copy changes
python3 tools/build-sitemap.py             # Also runs after build-releases.py and stamp-assets.py
```

Screenshot names decide where they land: a PNG called `world-map.png` becomes
`img/app-world-map.webp`, and a 900 px copy `img/app-world-map-900.webp` is
written beside it for `srcset` (cards and phones use it). The 1.1 pages use the
`app-v11-*` screenshots (whole screens) and `app-v11-card-*` (16:10 crops of
the same captures for the home cards); older `app-*` files remain for pages
that still cite them. Discover pictures go to `img/discover/<id>.webp` at
560 px through `build-discover.py`, which also rewrites the gallery between
its markers in `discover/index.html`.

The `--through` release argument names the newest version actually shared with
testers. It keeps later development notes and `unreleased.txt` off the public
site. Recheck the released note's date against the app repository before
regenerating; the 0.9.4 tag still contains an earlier date that was corrected
after release.

Supply a copy of `.github/release-notes/` from the released tag, rather than
the current development checkout (for example
`git archive v1.0.1 .github/release-notes | tar -x -C <dir>`). For 1.0.1 that is
the **v1.0.1 tag** (`707a933e2`); for 1.0 it was the v1.0.0 tag (`ba0b2633b`); for V16.1 it was the v0.9.18 tag (`23c56768a`); for V16 it was the v0.9.17 tag (`1b2078b10`); for V15 it was the v0.9.16 tag (`d1e767515`); for V14 it was the v0.9.15 tag (`59992dd2c`); for V13 it was the v0.9.14 tag (`eb466f9e9`); for V12 it was the v0.9.13 tag (`7d5b82c3`); for V9 it was the v0.9.10 tag (`02fd96f7`),

must describe its shipped tag only. The written guide and homepage quote the

The sitemap includes every canonical HTML page unless it has a `noindex` meta

## After changing CSS, JS or branding

```bash
python3 tools/stamp-assets.py
```

Every page references `/css/site.css?v=<hash>` and the scripts likewise;
self-hosted fonts, branding, product screenshots, social previews and the web manifest carry hashes
too. Changed files therefore get new URLs
instead of being served from a browser's one-year cache. Run this last — after
`build-legal.py`, `build-releases.py`, `build-faq-schema.py`, or font subsetting
have written their outputs. It stamps manifest icon URLs before hashing the
manifest itself, then refreshes the sitemap. Commit the restamped HTML and
sitemap together.

## Quick video guides

`/guide/videos/` contains six captioned walkthroughs recorded in released Delta V6
(0.9.7), linked from the homepage and the matching written guide sections. Each
player uses native browser controls, loads the MP4 only when requested, and has
an English VTT track, a poster, an expandable transcript and download links.
The videos are silent and already include visible captions; the optional VTT
track is available through the player's caption control.

Media lives in `media/guides/delta-v6/` (24 files, about 38 MB total). The source
bundle is `FantasyMap/outputs/website-guides/`; its manifest and validation report
record the durations and source revision (`v0.9.7`,
`53bfac611ad31ec1f9cd83ff324b17b4be9fefe3`). The app repo's
`tools/guide-videos/` contains the recording and rendering tools. Copy the MP4,
JPG, VTT and TXT together when replacing a guide, and update its duration,
download size and HTML transcript. Use a new version directory for a new
release; do not silently replace the recorded version. Media is served from the site’s own origin,
with a 30-day cache. The six MP4 files are each below 9 MB.

Guide media routes through `worker/media.js`: the deployed static-assets response
returned HTTP 200 for Range requests, which prevented browser seeking. The
handler streams single byte ranges with HTTP 206, a fixed content length and
the asset's original cache/security headers. Release file sizes in
`GUIDE_VIDEO_BYTES` supply lengths when the assets binding omits that header;
the runtime checks verify these sizes against every MP4. It supports suffix/open ranges,
rejects unsatisfiable ranges with 416, and sends the full file for unsupported
multipart ranges or stale If-Range validators. These media requests invoke the
existing Worker; other site pages remain static. No extra storage service is used.
The players use a version query to refresh media cached before range support.

With Miniflare available, run `node tools/test-media-ranges.mjs` for the focused
Worker checks. The first argument can point to an existing Miniflare module;
`WORKER_TEST_DATE` can select a compatibility date supported by an older local
runtime. Always check real seeking again after deployment.

The new page is included in the generated sitemap. Run font subsetting and
asset stamping after editing its copy, as for the rest of the site.

python3 tools/preview.py --port 8097
